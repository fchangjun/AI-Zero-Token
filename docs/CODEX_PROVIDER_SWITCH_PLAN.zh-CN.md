# Codex 原生与第三方服务切换方案

状态：接管实现已接入服务管理流程，已完成隔离集成验证；未发布安装包。更新日期：2026-09-29。

## 1. 要实现的行为

- 同一个本地对话可以在原生 Codex 服务、第三方 B、第三方 C 之间切换，保留 thread ID 和已有内容。
- 接管 B 后，新旧对话接下来的请求使用 B 的地址和凭证；接管 C 后使用 C。
- 解除接管统一回到原生 Codex/ChatGPT 登录服务，不回到此前的某个第三方。
- Codex 直接连接目标服务，AZT 负责切换本地设置，不转发模型请求。
- 原生状态使用内置 `openai`，以满足客户端对原生 provider 标识的检查。
- 切换期间暂停发送；已经在执行的请求先结束。切换成功后，后续请求才使用新服务。

这里的范围是所选 `CODEX_HOME` 中的本地会话，包括归档会话。其他电脑、远程主机和云端会话不在这次本地切换范围内。

## 2. 两种 Codex provider 身份

| 当前模式 | Codex provider ID | 连接和认证 |
| --- | --- | --- |
| 原生 | `openai` | 原生地址和 ChatGPT 登录 |
| 第三方 B | `azt_active` | B 的地址、Key、模型 |
| 第三方 C | `azt_active` | C 的地址、Key、模型 |

`azt_active` 是本方案拟使用的固定配置标识，不是新的中转服务。B、C 在 AZT 内仍有各自独立的服务记录、Key 和模型选择；只在 Codex 配置中共用一个活动入口。

原生与第三方互切时，需要更新会话的 provider 字段。B 与 C 互切时，该字段已经是 `azt_active` 的会话无需再次改名，但连接需要重新加载，模型也需要检查。

服务地址和实际使用的凭证决定请求使用哪一方账户。仅修改 provider 的显示名称不能改变请求归属。

## 3. 具体修改位置

以下是本机默认路径；实现时应尊重 `CODEX_HOME` 和 `AI_ZERO_TOKEN_HOME`，不能把这些绝对路径写死。

### 3.1 Codex 配置

文件：`/Users/baba/.codex/config.toml`

根级字段：

| 字段 | 第三方接管 | 解除接管 |
| --- | --- | --- |
| `model_provider` | `azt_active` | `openai`，或恢复等价的内置默认设置 |
| `model` | 目标服务的默认模型 | 可用的原生默认模型 |
| `model_reasoning_effort` | 按目标模型支持的设置调整 | 恢复原生设置 |
| `model_catalog_json` | 指向 AZT 生成的模型目录 | 恢复原生基线，原先未设置则移除 |

第三方连接写入同一个配置段：

```toml
[model_providers.azt_active]
name = "AI Zero Token"
base_url = "目标第三方的 API 地址"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
experimental_bearer_token = "目标第三方的 Key"
```

解除接管时，恢复原生连接设置，并移除 AZT 遗留的第三方 `openai_base_url` 覆盖。原生基线必须明确指向原生服务，不能简单恢复“接管前的任意配置”，因为接管前也可能是另一家第三方。

固定 provider 定义先保留；确认相关会话已迁移到原生后，移除其中的活动第三方 Key。解除接管不通过直接删除 provider 定义来实现。

### 3.2 模型目录

文件：`/Users/baba/.codex/model-catalogs/ai-zero-token-models.json`

接管时生成目标服务允许在 Codex 中使用的模型目录，包括 `models[].slug`、显示名称、推理强度选项、上下文和输入能力等。B 切换到 C 时更新这个目录。

模型目录负责提供模型选项；已有会话实际选中的模型还需要同步数据库，不能只更新目录或全局默认模型。

解除接管时停止引用 AZT 的目录，恢复原生目录配置。保留未被引用的目录文件不影响请求路由。

### 3.3 会话数据库

当前本机版本的文件：`/Users/baba/.codex/state_5.sqlite`

表：`threads`。通过 `id` 定位会话。

| 字段 | 更新规则 |
| --- | --- |
| `model_provider` | 原生为 `openai`，第三方为 `azt_active` |
| `model` | 设置为目标服务支持的实际模型 |
| `reasoning_effort` | 按目标模型支持范围调整；无已知支持值时清除。已验证原生 `high` → 第三方不发送 effort → 原生 `high` |

保留 thread ID、消息关联、标题、项目、工作目录和归档状态。数据库结构必须先检查；遇到未适配的版本就停止切换，不能猜字段或硬套旧结构。

实现直接更新数据库的这几个设置字段，前提是进程检查确认没有其他进程占用该 `CODEX_HOME`。备份使用 SQLite 的 `VACUUM INTO`，更新在 `BEGIN IMMEDIATE` 事务内执行，并核对旧字段值与行数，发现并发变更即失败。

### 3.4 会话 JSONL

位置：每个会话数据库记录的 `threads.rollout_path`。

AZT 不手工改写以下内容：

- 初始 `session_meta`。
- 已有用户消息、助手回复和工具记录。
- 已有 `thread_settings_applied` 设置事件。

也不需要 AZT 自己追加新的设置事件。当前版本的测试中，Codex 读取更新后的数据库设置，恢复并继续会话后自行追加新事件。

这是“AZT 不直接编辑 JSONL”，不是保证 JSONL 永远不再变化。用户继续聊天时，Codex 会照常写入。

### 3.5 登录与第三方 Key

原生登录：`/Users/baba/.codex/auth.json`，或用户配置的系统凭证存储。切换流程不把原生登录替换成第三方 Key。

AZT 服务记录：`/Users/baba/.ai-zero-token/.state/external-providers.json`。

- B、C 的 Key 保存在各自的 AZT 服务记录中。
- 接管时，把当前服务的 Key 写入 Codex 活动 provider 配置。因此，活动 Key 并非只存在 AZT 中。
- 解除接管后保留 AZT 保存的服务与 Key，方便再次接管；移除 Codex 活动配置中的第三方 Key。
- 验证切换完成后，再提交 `activeProviderId`、各服务的 `activeForCodex`、`codexNeedsApply` 和 `updatedAt`。
- `defaultModelId`、`models[].selectedForCodex` 保留各服务自己的选择，不因解除接管而清空。

### 3.6 切换状态与备份

已新增状态文件：`/Users/baba/.ai-zero-token/.state/codex-switch-state.json`，保存原生配置和会话模型偏好。

同目录的 `codex-switch-state.json.pending` 记录未完成操作的文件哈希、受影响会话设置及备份位置，不记录明文 Key。备份放在 `codex-switch-backups/<操作 ID>/`，目录权限为 `0700`，文件为 `0600`，配置备份和服务记录可能包含凭证。

配置文件、SQLite 和 AZT 状态文件无法由同一个数据库事务提交，需要阶段记录和恢复逻辑。进程异常退出后，必须先处理未完成的切换，再允许下一次切换。

## 4. 模型选择规则

为避免第三方模型不同导致旧会话继续使用不存在的模型，采用：

1. 接管目标服务时，如果当前模型仍在该服务启用的目录中，则保留。
2. 否则使用该服务在 AZT 中设置的默认模型。
3. 原生转第三方前，保存会话的原生模型和推理设置。
4. 解除接管时，优先恢复仍可用的原生模型偏好；第三方期间新建的会话、或原生模型已不可用的会话，使用当前原生默认模型。
5. 推理强度要跟随目标模型支持范围调整。

同名模型能否接受既有历史仍需目标服务支持；模型目录中的名称匹配不能保证历史兼容。

## 5. 三种切换流程

### 原生 → 第三方 B

1. 检查 B 的配置、Key、模型选择和本地数据库结构；识别有效配置中的覆盖项。
2. 等待当前请求结束，停止共享该 Codex 数据目录的相关后端，确认没有继续写入。若无法停止写入，则结束本次切换并报告原因。
3. 保存原生配置和模型偏好，创建一致性备份，记录切换阶段。
4. 写入 B 的活动 provider 配置、模型目录和默认模型。
5. 在 SQLite 事务中，把范围内会话设为 `azt_active`，并按规则调整模型与推理设置。
6. 检查配置和数据库一致，重新加载 Codex，核对恢复的会话设置和实际生效连接。
7. 验证完成后提交 AZT 的“B 已接管”状态，允许继续发送。

### 第三方 B → 第三方 C

同样先暂停写入、备份和记录阶段。将 `azt_active` 的地址、Key、模型目录、默认模型切换到 C。

已经使用 `azt_active` 的会话不需要修改 provider 名称；检查全部范围内会话的模型和推理设置，必要时更新，然后重新加载连接并核对结果。最后提交“C 已接管”。

### 第三方 → 解除接管

1. 等待当前请求结束，停止相关后端，备份并记录阶段。
2. 将全局 provider 恢复为原生 `openai`，恢复原生连接、模型目录和默认设置。
3. 在 SQLite 事务中，将范围内会话恢复为 `openai`，按规则恢复原生模型与推理设置。
4. 完成迁移核对后，移除 Codex 活动 provider 配置中的第三方 Key，保留兼容定义和 AZT 保存的服务资料。
5. 重新加载 Codex 并验证，清除 AZT 的活动第三方状态，允许继续发送。

实现会在提交前后检查写入进程，核对数据库字段和其他会话数据是否变化，校验配置、目录、偏好和服务记录的文件哈希，然后清除 pending 记录。macOS 桌面版只在会话尾部未发现未结束的 turn 时尝试正常退出客户端；不会强杀。不能确定空闲、退出失败、或有 CLI/IDE 占用目录时，操作失败并提示用户完全退出后重试。

客户端重新打开发生在本地提交完成之后。打开失败返回明确提示，不将已提交的设置误报成回滚；用户可以手动打开。Web/CLI 入口以及 Windows/Linux 目前要求用户先完全退出 Codex，切换后手动打开。

## 6. 失败恢复与旧版本兼容

- 切换过程中失败，在仍暂停写入时回滚配置和数据库，恢复到切换前的一致状态，并明确报告切换失败。
- 如果回滚也失败，保留备份与阶段记录，停止继续切换，不能显示“接管成功”。
- 成功接管后，第三方请求失败应直接报告错误，不自动改用原生账户发送。
- 不对已经重新开放、产生新消息的数据库直接覆盖旧备份；恢复逻辑必须识别是否已经产生新写入。
- 第一次升级时检查 `ai-zero-token`、`azt_external_*`、`azt_gateway` 等旧引用。按当前目标模式迁移其数据库设置；核对完成前保留兼容定义，暂不自动批量删除旧 provider。
- 数据库重建、仅从 JSONL 导入、其他 Codex 版本的恢复行为尚未验证。这些路径可能重新读到历史 provider，需单独测试和适配，不能承诺一次迁移后永久兼容所有版本。

## 7. 界面影响

沿用现有接管、切换服务、解除接管入口，不新增独立的 provider 管理页面。

需通过现有状态区域说明“正在切换、已完成、失败原因”；如需重启 Codex，应告知用户。原生模式使用 `openai`，第三方模式展示目标服务的模型。原生额度入口在第三方模式下仍可能受 Codex 自身判断限制，本方案不修改客户端代码。

## 8. 验证状态

已验证，本机 Codex `0.158.0-alpha.2.1`：

- 仅改全局配置并重启，不能保证旧会话跟随新 provider。
- 后端持续运行时，可能继续使用旧地址和旧凭证，因此切换必须处理运行中的连接。
- 在隔离配置中，停止后端，准备目标配置，只改 SQLite 的 `model_provider` 和 `model`，不编辑 JSONL，即可在同一会话完成原生 → B → 原生。
- 测试已覆盖 JSONL 中存在旧设置事件的情况。实际请求使用目标地址、目标凭证和目标模型，早期对话标记仍在请求中。
- Codex 在恢复并继续对话后自行追加设置事件。
- 第三方使用自定义 provider 可以设置 `supports_websockets = false`，避免已观察到的 WebSocket 重试。
- 本机客户端有按 provider ID 是否为 `openai` 判断的原生功能逻辑，因此原生模式保留内置标识。

上述数据库测试使用本地模拟接口和合成凭证，不是账单核验。此前真实账号测试验证了部分连接与模型组合，但不能代表所有第三方和历史内容都兼容。

新增自动化测试覆盖了归档会话、第三方期间新建会话、旧 provider 字段迁移、模型偏好恢复、推理设置清除、活动入口归属、写入进程阻断、最终服务记录提交失败、中断恢复、新消息保护、配置覆盖及客户端重开失败提示。另用 Node.js 22.12 的 sqlite3 后备实现验证了 1500 条会话设置往返切换。

`scripts/verify-codex-provider-switch.py` 调用实际 AZT 服务实现和本机 Codex app-server，验证同一 thread 的原生 → B → C → 原生，检查实际请求地址、凭证、模型、推理设置和历史标记；切换期间 JSONL 和原生认证文件哈希不变。接口和凭证均为本地模拟；原生阶段的地址由测试脚本重定向到模拟服务，未消耗真实额度。

仍未完成的平台验证：Windows/Linux 实机、关闭并重开正在使用的真实桌面客户端、数据库重建和仅从 JSONL 导入、其他 Codex 版本以及所有第三方模型的历史兼容性。未为验收中断用户正在进行的真实会话。

旧账号池配置入口保留；处于 `azt_active` 接管时会阻止旧入口直接覆盖连接，需先通过统一流程解除第三方接管，避免遗漏已有会话。
