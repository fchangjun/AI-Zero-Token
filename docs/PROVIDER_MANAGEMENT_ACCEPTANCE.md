# 模型与服务：验收说明

日期：2026-09-26；2026-09-28 更新。当前为 2.0.16 待验收版本，尚未发布。

2026-09-27 更新：“模型与服务”分为“接入外部 API”和“对外提供 API”。账号管理、可用模型、服务端口、轮换策略统一迁入对外服务；旧账号入口自动跳转。账号凭据沿用原文件。API 服务状态与本机 Codex 接入状态独立，支持可选 API 访问密钥及真实 Bearer 校验。

## 发布前复核（2026-09-27）

**结论：常规对话、Codex 流式请求、上下文压缩及压缩后续聊均已通过真实调用。** 本轮补齐当前 Codex 压缩协议，并检查打包后的桌面程序。正式发布前还需用户验收，以及 Windows 实机安装和运行检查。

复核中修复并新增回归测试：

- API 密钥更换与本机 Codex 接入配置并发时，旧密钥可能被写回。现在两者共用同一配置事务，接入操作在事务内读取最新密钥。
- 免密 API 模式下，局域网调用者可以访问账号导出等管理接口。现在所有管理接口始终仅限本机访问，模型 API 的可选鉴权保持独立。
- 桌面端 curl 流式响应快速结束时，会在读取响应头前删除临时文件，误报 502。现在读取完成后才清理；用延迟文件读取稳定复现，修复后短错误响应及 SSE 响应均通过。
- 旧的 Codex OAuth `/responses/compact` 上游地址返回 404。兼容入口现在使用 Responses 的 `compaction_trigger`，将结果转换为 `response.compaction` JSON，保留加密项与用量；截断、失败、缺少或重复压缩项会显式报错。
- 无模型缓存的新安装不再默认使用旧的 GPT-5.4。备用目录使用当前 GPT-6 模型，默认 GPT-6 Luna；首次网络同步的客户端版本更新为 0.155.0，后续仍遵循本机缓存版本与上游目录。缓存路径现在遵循 `CODEX_HOME`，隔离测试不再读取用户的模型缓存。
- 桌面退出后可能残留无窗口进程。现在等待服务及用量写入结束，在下一轮事件循环恢复退出；退出期间阻止窗口重新激活。已通过真实菜单退出检查，进程及监听端口均清理。

此前 `gpt-5.5` 返回 `model_not_found`，只能证明该模型在所测账号中不可用，不能据此判定网关整体异常。按 [OpenAI 官方模型说明](https://learn.chatgpt.com/docs/models)，5.5 已公告于 2026-10-14 从 ChatGPT 登录的 Codex 等产品退役，OpenAI API 不受此次退役影响。验收改用当前账号实际可用的模型。

接口测试页改为读取服务器当前生效的默认模型，避免使用已失效的历史设置生成示例。真实调用触发了正常的登录凭据刷新和用量记录；没有删除或重导入账号，仍为 129 个账号。

## 已完成的功能

- 独立“模型与服务”页面：服务列表、添加和编辑抽屉、模型详情、检测历史、Codex 接入选择。
- 自动获取 `/models` 返回的全部模型，也支持手动录入模型 ID。获取模型、检测能力和接入 Codex 分别操作。
- 每个服务独立保存凭据、模型和检测记录；同一时间只接入一个服务。未检测、繁忙、不兼容的模型都能勾选。
- 检测在后台执行，离开页面后继续，返回时可见进度和结果。暂时失败保留上次成功能力；首次检测中断时只展示已确认的能力。
- 自动导入旧版外部 API 配置及历史。编辑后提示重新应用到 Codex；删除活动服务恢复原来的默认配置。
- 配置、模型目录与最终保存作为一次操作处理。写入失败会恢复原配置；外部 API 凭据不出现在管理接口响应中；本机服务密钥仅通过专用本机接口读取，存储文件权限为 `0600`。

## 开始验收

在项目目录运行：

```bash
npm run preview:providers
```

打开终端打印的 `url`。默认使用随机空闲端口；可通过 `AZT_ACCEPTANCE_PORT` 指定端口。预览运行真实构建后的管理页面和接口，使用模拟上游、129 个虚拟账号及临时数据，不会覆盖正在使用的 Codex 配置。

建议按以下顺序验收：

1. 打开“验收示例 API”，确认成功、繁忙、不兼容、未检测的四个模型都显示。
2. 点击“接入 Codex”，用全部、已检测、检测通过、未检测、不兼容筛选模型，可与搜索叠加。“全选筛选结果”只影响当前显示的模型；隐藏的已选模型及默认模型应保留，取消默认模型时自动选择另一个已选模型。勾选任意状态模型、设置默认模型并保存；返回后确认选择被保留。
3. 接入“备用服务（手动模型）”，确认只有一个服务显示“当前接入”，原服务和历史仍在。
4. 编辑服务并保存，确认显示待应用提示；重新接入后提示消失。
5. 启动批量检测后离开页面，再返回查看结果；点击模型详情查看历史。
6. 打开“对外提供 API”，核对账号数、模型目录和轮换状态。在“账号池”搜索、筛选、批量选择；打开旧 `#accounts` 链接应进入同一位置。
7. 在“轮换策略”保存排除名单与并发设置，刷新后仍应保留；在“可用模型”调整 API 默认模型，系统设置应只显示全局代理、显示和日志选项。
8. 在隔离预览中启用访问密钥，验证缺失/错误密钥返回 401，正确密钥可读取模型；更换后旧密钥失效。生产环境沿用原鉴权配置，测试不会启用真实环境密钥。
9. 接入本机 Codex，再切到外部服务，账号池 API 应继续可调用。已接入本机服务时更换密钥应同步更新临时 Codex 配置。
10. 在服务概览核对实际监听地址，复制调用配置；页面窄窗口应正常换行。

真实服务的网络可用性和新建 Codex 对话仍需用目标服务验收。已有对话中的加密历史兼容性属于上游协议问题，本次管理功能不对其作修复承诺。已构建本地安装包，尚未执行 npm 发布、GitHub Release 或安装包上传；正式发布时继续使用项目既定发布流程。
